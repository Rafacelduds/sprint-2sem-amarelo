`gtfs_captures` e `gtfs_versions` estavam vazias e `/network/catalog` retornava

`pipefail\r: invalid option name`. Normalização para LF e execução do script
criaram `raw-data`, com versionamento. `.gitattributes` preserva LF nos próximos
checkouts. Nenhum volume foi removido.

`https://www.sptrans.com.br/umbraco/Surface/PerfilDesenvolvedor/BaixarGTFS`,
`source_id=sptrans`, captura `2026-11-20T22:16:52.383354Z`
(19:16:52 em São Paulo). ZIP original preservado com 14.326.297 bytes:

```text

```

Chave `gtfs/sptrans/<hash>.zip`. Uma captura e uma versão no PostgreSQL.
Leitura posterior do corpo do objeto S3 recalculou SHA-256 e tamanho, ambos
iguais ao catálogo. Extensão de calendário: 01/10/2023–01/06/2027,
`calendar_extent`; não é comprovação de vigência de cada linha/data.

API e web reconstruídos e reiniciados. A API anterior não tinha credencial
Olho Vivo; reutilizada a existente em `apps/api/.env`, sem registrar valor.
Configuração transitória para Docker: hosts `postgres`/`s3`, `VITE_API_URL=/api`.
Não foram editados `.env` nem iniciados coletores contínuos ou alertas.
O catálogo após reinício manteve versão e captura, `status=ready` e 1.893
entradas de linha/sentido: 1.711 `matched` e 182 `unmatched`, sem `ambiguous`
nessa amostra. Contagens dependem do snapshot e não certificam toda a rede.
Resposta consultada preservada localmente em `data/us02-produto-catalog.json`
(ignorada pelo Git).
